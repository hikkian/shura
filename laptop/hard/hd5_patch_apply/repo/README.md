# patchlib

Применение unified diff (один файл) к строке. Без внешних программ.

```python
from patchlib import apply_patch, PatchError, ConflictError
new_text = apply_patch(old_text, patch_text)               # вперёд: old -> new
old_text = apply_patch(new_text, patch_text, reverse=True)  # назад: new -> old
```

## Формат патча

* Всё до первой строки `@@` (заголовки `diff`, `index`, `---`, `+++` и т.п.) игнорируется.
* Заголовок ханка: `@@ -a[,b] +c[,d] @@` и необязательный текст после. Пропущенный счётчик означает 1.
  `a` — номер первой строки старого файла (с 1), `c` — нового. Если счётчик 0, номер указывает на строку
  *перед* местом вставки/удаления (`@@ -3,0 +4,2 @@` — вставка после третьей строки; `-0,0` — в начало).
* Тело ханка — ровно `b` строк старой стороны (контекст ` ` и удаляемые `-`) и `d` строк новой стороны
  (контекст и добавляемые `+`). Границу ханка определяют эти счётчики, а не вид строк. Пустая строка внутри ханка —
  пустая контекстная строка (редакторы убирают одинокий пробел). Строка `\ No newline at end of file` относится
  к строке перед ней: после ` ` — к обеим сторонам, после `-` — к старой, после `+` — к новой; в счётчики не входит. Маркер допустим только сразу после последней строки соответствующей стороны
  ханка (для `-` — последней строки старой стороны, для `+` — новой, для ` ` — последней строки обеих сторон); в любом другом
  месте — `PatchError`.
* Патч, как и текст, делится на строки только по `\n`; `\r`, `\f` и т.п. внутри строк — обычные символы.
* После ханка допускаются только следующий ханк или конец патча (пустые строки в конце игнорируются).

## Применение

* Текст делится на строки только по `\n`; `\r`, `\f`, U+2028 и т.п. — обычные символы внутри строки.
  Последняя строка может быть без `\n`; это часть её содержимого (`"a"` и `"a\n"` — разные строки).
* Ханки применяются по порядку, без пересечений. Строки старой стороны ханка должны совпасть с файлом
  символ в символ (пробелы в конце тоже), нечёткого совпадения нет.
* Ожидаемая позиция ханка — его номер строки в заголовке плюс смещение предыдущего применённого ханка
  (его фактическая позиция минус позиция из его заголовка; для первого ханка смещение 0). Если по ожидаемой позиции не совпало, берётся ближайшая подходящая
  позиция не раньше конца предыдущего ханка; при равном расстоянии — более ранняя.
* Если ханк нигде не подходит — `ConflictError` с атрибутом `hunk` (номер ханка с 1); результата нет, ничего не меняется.
* Неверно оформленный патч (счётчики не сходятся, лишние или неизвестные строки, нет ни одного ханка,
  неверный заголовок) — `PatchError`, но не `ConflictError`. `ConflictError` — подкласс `PatchError`.
* `reverse=True` меняет стороны местами (`-` и `+`, `-a,b` и `+c,d`).
