# ideal5 — specification (decisions made by the main session; implementers do not change them)

Base: `gen7/{ornith,qwen36}-ideal4.jinja` generated by `make_templates.py` (effort "ideal4").
Goal: (1) every earlier prompt is an exact byte prefix of the next turn's prompt (KV-cache reuse); (2) no wording
that was written to fix one specific benchmark task.

## A. Cache stability (hard requirements)
A1. The system block is byte-identical on every turn of a conversation for a fixed effort / thinking setting.
    It may depend on `reasoning_effort`, `terse`, tools — never on message content.
A2. No past message is ever changed by a later turn. Nothing is appended to or inserted into any user, tool or
    assistant message. In particular REMOVE the reminder text that ideal4 appends to the last user/tool message
    (REMIND3 for medium/high/xhigh/max, RU_REM, KZ_REM, MIX_LINE reminder). No reminder block is added after the history either.
A3. The language anchor becomes ONE fixed sentence, always present (also for English-only chats), appended at the end of the system block
    right before the effort line (so the effort line stays the last line):
    "Write everything addressed to the user (short notes between steps and the final answer) in the language of the user's latest message. Keep code, commands, paths and identifiers as they are, and keep established technical terms, names and parameter values (API, commit, endpoint, high, xhigh) as developers in that language write them; do not translate them."
    Delete the whole language-detection Jinja block (LANG_BLOCK / LANG_BLOCK4, RU_LINE, KZ_LINE, MIX_LINE, `<context>` skipping) — it is no longer needed.
    (The gateway `lang_guard.py` stays as the backstop for Russian/Kazakh; it is outside the template.)
A4. Effort = one line at the END of the system block. Levels: fast = thinking off (no text), low, medium, high, xhigh, max.
    ideal4 gave medium no system text; keep that (medium = native calibration), but see A5.
A5. Keep from ideal4: leading system messages merged; preserve_thinking default ON (`ornith`: always true; `qwen36`: kwarg default true);
    `enable_thinking=false` renders the closed empty think block exactly as the official template; string tool arguments tolerated;
    control-token defusing in user/tool text; tools block and `<tool_call>` XML format byte-identical to the official qwen3-coder format;
    mid-conversation system messages rendered, no "No user query" crash.
A6. Check explicitly that the way the agent re-sends a previous assistant turn (reasoning_content + content + tool_calls) renders to the same bytes
    as what the generation prompt + the model output produced (the classic break: `<think>\n` opened by the generation prompt vs a full
    `<think>…</think>` block in history). If the official template has an unavoidable mismatch here, document it in RULES.md with the
    exact bytes, and do not "fix" it by changing the official rendering — report it.

## B. Rules: general principles, no task fingerprints
Each effort line is rewritten from the ideal4 text (IDEAL3 dict) with these replacements; keep the tier structure
(high < xhigh < max in depth; low short; max = bigger thinking budget + adversarial self-review, AT MOST TWO ROUNDS, no review subagent unless the user asks).
| ideal4 rule | ideal5 principle (use this wording or very close) |
|---|---|
| EX4 "with one small script extract every code block from the file … fresh interpreter" | "run what you deliver the way the user will: execute every code example and command you put in a file or in the answer exactly as written, in a clean context, and fix whatever fails" |
| IMG4 "transcribe all visible text of the mockup … item by item" | "ground your work in the inputs: before building, list the concrete facts the inputs state (text, numbers, structure, error messages) and compare your result with that list before answering" |
| "State only what you verified, and say plainly what you could not verify" | keep; add: "if the request cannot be fulfilled as stated (missing access or information), say so and what you need instead of simulating it" |
| edge-case / diff / tests items | keep (already general) |
| max adversarial review | keep, at most two rounds, stop when a round finds no real defect |
Do not mention: mockups, README, extract/script, blocks, interpreter, transcription, specific file types.
