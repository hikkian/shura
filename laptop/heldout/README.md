# tasks_heldout: 5 новых задач для честного сравнения шаблонов

Те же ТИПЫ, что t1..t19, но другие задания (не использовались при подборе промптов). Формат как в `gen8/TASK-FORMAT.md`: `prompt.txt`, `repo/`, `hidden_test.py` (`python -m unittest hidden_test`, cwd=check), `attach.png` (только h4). Эталонные решения лежат в `<task>/reference/` вне `repo/` и бенчем не используются. Хеши этого каталога считает отдельный шаг (HELDOUT_HASHES.txt).

Время оценено для модели ~39 tok/s: агентный прогон + тест. Тест всегда занимает < 1 с (h4 около 1 с), так что время определяется агентом.

| задача | тип | что меряет | прогон агента (оценка) |

| h1_shop_discount | Python, 3 модуля + visible tests | правка нескольких файлов по неполной постановке | 6-12 мин |

| h5_ci_cause | анализ данных, текст | ранняя причина вместо громкой, без выдумок | 3-6 мин |

## h1_shop_discount
Пакет `shop/` (money, cart, report) + `tests/test_shop.py` (проходит на стартере; в нём нет edge cases). Промпт: скидки «то на 1 меньше, то на 1 больше», цены с потерей копейки, невалидные цены -> ValueError, строка скидки в `render(cart, pct=0)`.
Ловушки: `round()` в Python округляет к чётному (2.5 -> 2), `int(float(s)*100)` теряет копейку (19.99 -> 1998), `fmt` ломает отрицательные суммы (-101 -> "-2.99"; нужно для строки скидки), 3 знака после запятой («1.005») и мусор должны давать ValueError, pct вне 0..100 (в промпте не сказано, но вытекает из докстринга), дробные pct (12.5), пустая корзина, Unicode в названиях.
Hidden test: 9 тестов (точный парсинг, невалидные, half-up, total, bad pct, пустая корзина, fmt<0, render со скидкой, render без скидки не изменился). Стартер падает (6 failures, 3 errors).
Ограничение: сигнатура `render(cart, pct=0)` названа в промпте, иначе тест нечестен.

## h2_js_pool
`lib/pool.js` с `mapLimit`; контракт в JSDoc-комментарии, а не в промпте. package.json как у t6 (`type: module`, `node --test`, без npm). Стартер: результаты в порядке завершения, `fn` без индекса, лимит не валидируется, после ошибки воркеры продолжают брать задания.
Ловушки: порядок + индекс, лимит достигается и не превышается, `limit=1` строго последовательно, falsy/undefined-результаты, синхронный `fn` (в том числе бросающий), невалидный limit (0, -1, 1.5, NaN, "2", undefined) -> reject с RangeError (async-функция, не sync throw), после ошибки новые задания не стартуют (<=4 стартов, и счётчик не растёт через 60 мс).
Hidden test: один скрипт `_hidden.mjs` (как t6) с assert; visible `test/pool.test.js` падает на стартере. ~0.3 с.

## h3_readme_envconf
Библиотека `envconf` (`load, Field, Config, ConfigError, parse_bool`), `tests/` есть и проходят. Неочевидное: `load(schema, *, prefix, environ=None)` (prefix обязателен и только по имени), имя переменной `PREFIX_NAME` в верхнем регистре, пустая строка = отсутствует, `ConfigError.errors` собирает все ошибки, `Config` без `cfg["x"]`, `as_dict()` маскирует `secret` на `***`, `parse_bool("")` -> ValueError, `Field(list, sep=...)`. Примеры «по догадке» (`load(schema)`, `cfg["port"]`, без environ с чужими переменными) падают.
Hidden test (по образцу t12): хеши исходников (код не менять), README > 1200 символов, каждое из 5 имён есть в тексте и в code-блоках, >=3 python-блока, каждый блок запускается в чистом интерпретаторе (допустим префикс из предыдущих блоков; окружение очищено от APP_/DB_/MYAPP_/SVC_), в примерах есть `prefix=`, `except ConfigError`, `.errors`, `as_dict`; доля кириллицы в прозе > 0.6 при > 400 букв.

## h4_invoice_mockup
`attach.png` 1000x700 (счёт: тёмно-синяя шапка, заголовок «Счёт № 117/2025», бейдж «Оплачен частично», таблица из 4 позиций с ₸, выделенная жёлтым жирная 3-я строка, подытог, «Скидка 10%» с «–35 550 ₸», итог, подвал с «©», «БИН», «150/230»). Сгенерирован из `reference/index.html` через headless chromium; арифметика сходится (355 500 – 10% = 319 950).
Ловушки: точные строки (₸, №, «», –, %, ё в «Счёт»), настоящая таблица с 5 колонками и заголовками, выравнивание сумм по правому краю, выделенная строка (светло-жёлтый фон и жирность, остальные не жирные), бейдж (светлый оранжевый фон, тёмный текст, скругление, справа сверху), тёмная шапка, крупный итог, подвал внизу.
Hidden test: Playwright (venv `aiym/.venv`, с тем же fallback на chromium из ~/.cache, как у t16), 9 тестов, один запуск браузера (~1 с, таймаут subprocess 90 с), скриншот в `$SHOT_DIR/h4.png`. Нет консольных ошибок/внешних ресурсов/горизонтальной прокрутки.

## h5_ci_cause
Папка с `ci_runs.csv`, `git_log.txt`, `failures.log`, `README.md`. Реальная причина самая ранняя и самая тихая: коммит d4e8b17 (среда 16:48, «cleanup requirements.txt») снял пин `tzdata==2023.3`; его прогон был зелёным (закешированный образ), а ночная пересборка 13.03 в 02:00 подтянула tzdata 2025.1 (Asia/Almaty +05 вместо +06), первый красный прогон 02:14. Громкие отвлекающие факторы: рефакторинг округления f0c9a2e в четверг (добавил 2 своих падения), таймауты registry.
Hidden test (по образцу t14/t19, `ANSWER_FILE`): файлы не изменены и нет лишних; назван `d4e8b17`; упомянуты tzdata + снятие/версия + пояс/Almaty/utcoffset; объяснено, почему среда была зелёной (кеш/ночная пересборка); время начала 02:00/02:04/02:14 и четверг/ночь; предложение, называющее причиной f0c9a2e/округление/registry, должно быть отрицанием или содержать d4e8b17/tzdata; запрещены выдуманные факты (обновление Python, OOM и т. п.); доля кириллицы > 0.7 после удаления кода/хешей/путей.
Эталонный ответ: `reference/answer.txt` (проходит). Проверено на пустом ответе (6 из 9 падают), на ответе-симптоме (7 падают).
