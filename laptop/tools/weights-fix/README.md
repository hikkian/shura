# Починка русских опечаток на уровне весов без обучения (ноутбук, 10.11.2026)

**Итог:** в рабочей модели подняты до 4 бит (Q4_K) эксперты ПОСЛЕДНЕГО слоя (39) вместо Q2_K. Файл +0,176 ГиБ (13,4 → 13,6 ГБ), свободная память с загруженным агентом не изменилась (5,49 против 5,50–5,61 ГБ), скорость та же (37,6–38,4 против 36,4–38,3 ток/с), видеопамять та же (5,76 ГБ).
Качество (24 настоящие опечатки Ornith + контроль на коде; перплексия на русском тексте): запас правильной буквы 1,73 → 2,38, правильное слово первым 67% → 75%, код 5,26 → 5,38 (не хуже), перплексия 5,734 → 5,629.

## Диагноз
- Всё, кроме экспертов, у нашей модели уже в Q8_0/F32 (внимание, общие эксперты, маршрутизатор). От несжатой версии отличаются только эксперты (Q2_K/Q3_K), таблица слов и выходной слой (Q4_K).
- Таблица слов и выходной слой в Q8_0: почти нет эффекта (запас 1,59 и 1,66, перплексия 5,73 и 5,69).
- Эксперты по группам слоёв (Q4_K_M из Q8_0): слои 10–19 → 1,89/5,74; 20–29 → 2,03/5,68; 30–39 → 2,33/5,52; уточнение: слои 38–39 → 2,53/5,61; слой 39 отдельно → 2,43/5,63 (+0,24 ГиБ, но с Q6_K в down → +1 ГБ RAM!); слой 38 отдельно → 1,76/5,72; слои 37–39 → 2,30/5,59; слой 39 в Q8 → 2,48/5,62.
- Слой 39 по частям: gate+up → 1,94/5,66; down → 2,18/5,70.
- **Q6_K в down-экспертах (донор Q4_K_M) стоил ~1 ГБ лишней оперативной памяти** (при +0,24 ГиБ файла); чистый Q4_K (`--pure`) эту проблему снял.
- Несжатая Q8_0 (запас 3,48) всё равно лучше: часть опечаток остаётся свойством самой модели и лечится только дообучением.
- Память ноутбука: эксперты (~11 ГБ) лежат в оперативной (shmem), кэш контекста и кэш экспертов в видеопамяти, поэтому подъём экспертов влияет только на RAM.

## Как повторить
1. Донор: `llama-quantize --allow-requantize --pure Q8_0.gguf donor-Q4_K-pure.gguf Q4_K 8` (из Q8_0-файла Ornith, 6 минут).
2. Подмена: `splice_gguf.py --base <3bit-MTP.gguf> --donor donor-Q4_K-pure.gguf --out <out.gguf> --layers 39 --kinds ffn_gate_exps,ffn_up_exps,ffn_down_exps` (есть `--dry-run` и `--names` для тензоров вне слоёв; python из venv с numpy; gguf-py берётся из `~/.unsloth/llama.cpp/gguf-py`, если shura gguf-py не импортируется).
3. Замеры: `eval_variant.sh model label` (сервер на 8092 + `bench/rufix/margin.py` + `llama-perplexity` на `ru_eval.txt`, который делает `make_ru_eval.py`), `measure_comfort.py модель1 модель2 ...` (свободная память, RSS, VRAM, скорость, через шлюз).
4. Откат: `rollback-l39p.sh` (возвращает прежний путь модели в `model-launch.json`).
Результаты замеров: `results.jsonl`, логи `scan*.log`, `pure_test.log`.

## Ограничения
- 24 опечатки это малая выборка; для контроля взята перплексия на отдельном тексте, она показывает тот же знак, но эффект скромный (−1,8%).
- Основной источник опечаток (2–3-битные эксперты других слоёв) остаётся; полный фикс на ПК: более высокий квант или перефит кодов (`bench/rufix/IDEAS.md`).
