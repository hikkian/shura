# Prefill yield: кеш экспертов на 0 слотов на время большого префилла

Выключено по умолчанию (`prefillCacheYield: false`). Включать только по решению пользователя: ответы при `temperature 0` при
нулевом кеше отличаются от кешированного пути (PREFILL2b: KL 0.140 против шума разных `-ub` 0.104, top-1 96.9%).

## Ключи guardian.json

| ключ | по умолчанию | что делает |
|---|---|---|
| `prefillCacheYield` | `false` | включает путь; при `true` сервер запускается с `--moe-cache-live-resize` |
| `prefillCacheYieldMinTokens` | `4000` | порог новых токенов запроса (оценка: символы тела / 4; первый запрос или более короткое тело = новый разговор, считается всё тело) |

Несовместим с `slotGears` (оба меняют число слотов): шлюз не стартует с обоими включёнными.

## Что происходит с одним запросом

1. Запрос прошёл `acquire_model`, сервер READY, идёт только он (`busy == 1`), запрос большой (≥ порога), не vision, не игра.
2. `POST /moe-cache/slots {"slots": 0}`, таймаут 5 с. Запрос до сервера ещё не отправлен, поэтому ресайз идёт на простое.
3. Запрос отправляется как обычно (префилл идёт без пакетов кеша).
4. В `finally` (после ответа, при обрыве клиента тоже) `POST /moe-cache/slots {"slots": N}` с уровнем, который был до шага 2 (то есть уровнем клапана VRAM, если клапан его уже понизил, а не максимумом).

Клапан VRAM не вмешивается, пока не вернули слоты: `vram_valve_tick` пропускает такт, если восстановление ещё должно.

## Отказ

- Ресайз вниз не удался (HTTP ошибка, отказ сервера, исключение): запрос идёт как есть, событие `prefill_yield_failed`, счётчик `resize_failed`.
- Ресайз вверх не удался: уровень запоминается как долг (`pending`), событие `prefill_yield_restore_failed`. Монитор повторяет его, когда сервер простаивает; клапан до этого не трогает кеш. Если сервер сменился, долг аннулируется (`prefill_yield_restore_void`): новый сервер стартует с настроенным числом слотов.

## Наблюдаемость

- События: `prefill_yield_started`, `prefill_yield_restored`, `prefill_yield_failed`, `prefill_yield_restore_failed`, `prefill_yield_restore_void`.
- Статус (`status_snapshot`): блок `prefill_yield` со счётчиками `yielded`, `restored`, `resize_failed`, `restore_failed`, `skipped` и текущим `pending`.

## Не проверено на настоящем сервере

Живой проверки здесь нет: измерения PREFILL2/PREFILL2b сделаны вручную (+14…+18% префилла при 7k и 24k). Тесты используют фальшивый сервер (`tests/support/fake_llama_server.py`, маршрут `/moe-cache/slots`, отказ по `resize_status`). Включать в живом config только после живой проверки через тестовый шлюз.
