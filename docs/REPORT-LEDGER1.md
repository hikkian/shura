# LEDGER1 — отчёт

## Что сделано

- Добавлено локальное SQLite-хранилище журнала `gateway/experience_ledger.py`. По умолчанию файл находится в `~/.local/share/shura/experience.sqlite`; каталог закрыт правами `0700`, файл — `0600`. WAL выключен, включены `synchronous=FULL` и `secure_delete`.
- Добавлены записи задач (запрос, снимок репозитория, проверки, репозиторий), исходов (принят, исправлен, отклонён и результаты тестов), пар «ответ — правка», решений ворот, сырых ответов экзамена и упорядоченного стека проверенных состояний карт.
- Добавлены согласия с отдельным переключателем для захвата, якоря роста, недельной доли принятых без правок и экзамена. Запись задач/исходов/правок требует согласия `capture`; экзаменационный ответ — `exam`; якорь — `growth`. Недельная доля считается только при отдельном `weekly_acceptance` и нигде не участвует в отборе задач.
- Разделение по блоку (репозиторий, временной отрезок или явная метка) детерминировано SHA-256 от локальной соли и имени блока; решение сохраняется. Вероятности: 2/3 обучение, 1/3 экзамен; 10% экзамена запечатано (около 3,3% всех блоков). Пересчитать солью извне назначение нельзя: соль не экспортируется.
- «Забыть» заменяет полезную нагрузку записью-надгробием с SHA-256, включает очистку SQLite и VACUUM. Для стека карты приватность наследуется от исходных записей; экспорт JSONL включает только открытые записи. Рецепт пропускает состояния, ссылающиеся на стёртые источники.
- Добавлен путь миграции LL6 capture через чтение существующей SQLite-базы; повторная миграция не дублирует уже перенесённые события.
- Добавлен API `/guardian/experience/*` под новым флагом `experienceLedger: false`. Есть управление согласиями, запись видов событий, список, экспорт, сводка роста, статистика, миграция и forget. Для forget нужен локальный токен подтверждения. Действующие настройки gateway не менялись; включение флагов не делалось.

## Числа и оценка записи на диск

- Тесты нового журнала: 5/5 пройдены. Тесты существующего хранилища: 42/42 пройдены.
- В `stats` указан плановый бюджет записи около 100 KiB/день. Это оценка, а не замер на живом gateway: грубое допущение — порядка 25 задач в день по несколько килобайт с исходами и индексными/SQLite-накладными расходами. Даже при 100 KiB/день получается около 36,5 MiB/год записей. Отдельный замер физического write amplification SSD не проводился.
- Временная БД теста с одной задачей физически не содержала удалённый текст после forget и VACUUM; идентификатор и SHA-256 остались.

## Не сделано и почему

- Не запускался полный gateway API end-to-end: локальные сокеты запрещены sandbox.
- Независимое ревью Sonnet high не запускалось: такого инструмента в доступной среде нет.
- Не запускался Barid finish и не делался git commit — по инструкции пользователя это выполняет оркестратор.
- Не проверялась миграция на пользовательской базе LL6 и не включались флаги в конфигурации.

## Неожиданное

Тестовый gateway harness блокируется политикой sandbox ещё до старта сервера, при попытке занять свободный порт. Поэтому unit-тесты и компиляция подтверждают хранилище и синтаксис, но не заменяют сетевую проверку маршрута.
