3. Исправления и задания без указанного автора записываются как `unknown`.
4. У исхода хранится список авторов контекста и признак `context_clean`.

6. Флаг `experienceLedger` остался выключенным; настройки и живой Shura не затрагивались.
7. История LEDGER2 до этой работы отсутствовала: в ней были только LEDGER1 и NOTE0.

## Что было и что изменено

Проверены история Git и рабочее дерево по всем разрешённым файлам. Коммита LEDGER2 и прежних изменений этих файлов не было. Уже существовали LEDGER1: SQLite-журнал, согласия, стирание с хешем, разбиение на экзамен/обучение и отсев удалённых источников в рецепте; в хранилище памяти уже были паспорта `source` и `confirmed_by`; NOTE0 уже добавил тонкую команду `count_real_pairs.py`.

Сохранены эти механизмы и добавлены авторы, фильтр обучения, авторская статистика, поля API, тесты и счётчик по реальным полям. `lifelong_request.py` не менялся: чтение памяти там знает ID найденных записей, но путь записи исхода не соединён с этим чтением и не передаёт контекст журналу. Для такой сквозной передачи нужен отдельный способ связать запрос и исход; сейчас API принимает `context` (авторов или объекты авторов) явно. Это оставлено как незавершённая интеграция.

## Хранение и старые записи

Выбран минимальный вариант: nullable-столбец `author` в `events`, `memory` и `rule`, добавляемый через `ALTER TABLE` только при его отсутствии. Текст по-прежнему хранится в существующем payload/строках, отдельной таблицы текста нет. Старые строки при чтении получают автора на лету: `user_command` → `human`; `user_confirmed_proposal` → `local_model`; `import`, `import-legacy`, `capture`, `external:*` → `unknown`. Старые события без столбца и tombstone также читаются как `unknown`; forget сохраняет SHA-256 и стирает текст как прежде.

Новые записи памяти принимают `author`; если он опущен, применяется соответствие существующему `source`. Ошибочный класс отклоняется. В API опыта ошибочный класс даёт HTTP 400 через общий валидатор. Для `add_task` и `add_correction` значение по умолчанию — `unknown`. Для исхода без сведений о контексте `context_clean=false`; наличие любого автора кроме `human` и `local_model` тоже делает его false.

`trainable` отказывает для текстовых событий с автором `closed_ai`/`unknown`, нечистых или неизвестных по контексту исходов, забытых записей, а также событий из `exam` и `sealed_exam`. Рецепт стека отдельно возвращает `omitted_untrainable_source_ids`, не меняя состояния с чистыми источниками. `export()` по-прежнему отбирает по приватности и показывает автора в каждой записи. Статистика считает авторов и чистые/нечистые исходы.

Оценка роста: обычная задача или исправление прибавляет примерно 10–20 байт на автора в SQLite (значение автора и заголовок записи). Исход дополнительно хранит `context_authors` и `context_clean`, обычно ещё около 40–70 байт; суммарный рост типичного события — десятки байт, без копии текста и новой таблицы. Это оценка формата записи, не замер физической записи SSD.

## Что всё ещё может пропустить текст закрытого ИИ

- Человек может вставить текст закрытого ИИ и обозначить его как собственный; происхождение по самому тексту надёжно не определить.
- Контекстный урок, добавленный путём, который не сообщает ID/автора урока в `context`, не обнаруживается; сейчас такой исход консервативно помечается нечистым только когда поле контекста отсутствует целиком.
- Пока не подключена автоматическая передача ID уроков из `lifelong_request.py` в запись исхода. До этой связи корректность зависит от вызывающей стороны, передающей `context`.

## Не сделано и почему

Не запускался gateway end-to-end: локальные сокеты запрещены карточкой. Не менялись `experienceLedger` и живые настройки. Не читались пользовательские базы. Полная передача ID контекстных записей через запрос и исход оставлена отдельно, поскольку нынешний путь `lifelong_request` не имеет связи с endpoint записи исходов. Числа NOTE0 остаются только агрегатами; теперь они читают реальные поля автора и чистоты, не печатая текст.
