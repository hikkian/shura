# SWCOUNT1 — выключатель и счётчик

## Сделано

В `gateway/switch_counter.py` добавлена проверка строки экзамена по общей доле срабатываний. Она объединяет события разных выключателей логическим «ИЛИ» по независимому идентификатору семьи: если хотя бы один выключатель сработал на семье, эта семья считается один раз. Проверка использует одностороннюю точную границу Клоппера — Пирсона и делит заданный уровень значимости на заранее объявленное число проверок. Добавлен метод `SwitchCounter.shared_row` для оценки такой строки по накопленным записям.

Тесты проверяют объединение выключателей, устранение повторного счёта семьи и поправку на повторные проверки. Существующие тесты также проверяют salted ID, отсутствие текста запросов в экспорте, согласие `capture`, дневной предохранитель, исключение `/teach` и разбор потокового ответа тормоза.

## Числа и ограничение

Для δ = 0,03, 100 независимых семей и одной заранее запланированной проверки с нулём срабатываний верхняя граница равна **0,029513**, строка закрывается. Это воспроизводит порог MASTER §5а.

Если заранее заложить 28 проверок с поправкой Бонферрони (α = 0,05 / 28), та же граница становится **0,061319** и строка не закрывается. Значит, одновременное требование «не чаще 5 % ложных закрытий при повторном заглядывании» и «закрыть строку при 0/100» этой простой поправкой не выполнено. Для SWCOUNT1 нужен последовательный доверительный предел/э-процесс или фиксированное правило момента проверки; до этого многократное применение одиночной 95%-й границы небезопасно. Текущая функция консервативно тратит α по заданному числу проверок и не скрывает этот конфликт.

Предохранитель для живого режима остаётся дневным, использует заранее разделённый α и только переводит обычные навыки обратно в тень. Правила `/teach` он не снимает. Автоматическое включение кандидатов не добавлено. Флаги в конфигурации шлюза остаются выключенными по умолчанию.

## Проверки

Команда `python3 -m unittest tests.test_switch_counter -v` завершилась с ошибкой на трёх сквозных тестах. 14 остальных тестов прошли. Все три ошибки возникли при попытке shura-qa создать локальный сокет: среда вернула `PermissionError: [Errno 1] Operation not permitted` ещё до запуска шлюза.

```text
Ran 14 tests in 0.114s
OK
```

Также выполнено:


Обе команды завершились с кодом 0. GPU и сеть не использовались. Независимое ревью Sonnet не проводилось: такой инструмент в доступной среде отсутствует.

## Не сделано

- Не выполнена полноценная симуляция повторного заглядывания для семей задач. Точные расчёты выше показывают, что простое деление α не удовлетворяет порогу 0/100; подменять это обещанием симуляции было бы неверно.
- Проверка общей строки добавлена как API счётчика, но подключение её к обвязке экзамена и манифесту δ требует интерфейса этих компонентов.
- Сквозная проверка шлюза заблокирована запретом локальных сокетов в среде.
- В `PROMPT-SWCOUNT1.md` находится только заголовок/метка задачи. Объём работ восстановлен по MASTER §5а, REPORT-FRESH1 и уже имеющемуся коду SWCOUNT1.
