# PUB5: калибровка прогноза скорости для Vulkan по открытым данным

Исполнитель: Claude Haiku 5.5 (линия claude2). Дата: 2026-10-20.
Итог: **partial**. Таблица карт с источниками и коэффициенты готовы. Подпись «оценка, ±X %» в выводе установщика и
коэффициенты в `planner.py` не внесены: код установщика по правилам задачи не трогал (его правит PUB3).

## Что сделано

1. **Таблица карт с источниками.** Плотная модель Llama 2 7B Q4_0, Vulkan, без флеш-внимания: 30 строк scoreboard
   [#10879](https://github.com/ggml-org/llama.cpp/discussions/10879) и 3 строки комментариев; MoE Qwen3-30B-A3B Q4_K_M:
   3 строки из [поста на форуме Radxa](https://forum.radxa.com/t/llama-cpp-benchmarks/27813/17). У каждой строки есть
   источник в CSV (`reports/pub5/vulkan_rows.csv`) и в документе `docs/SPEED-ESTIMATES.md`.
2. **Эффективность** (tok/s × байты за токен / пиковая пропускная способность). Расчёт воспроизводится командой
   `python3 reports/pub5/calibrate_vulkan.py reports/pub5`.
3. **Коэффициенты:** плотные модели на Vulkan **0.67**, MoE на Vulkan **0.12** (низкая уверенность). Записаны в
   `catalog/speed-calibration-vulkan.json`.
4. **Предлагаемые подписи:** плотные «оценка, ±20 %»; MoE «оценка, ±50 %; мало данных».
5. **Опорная точка:** наши HIP-замеры RX 7800 XT (REPORT-LAYOUT1c: декод 44.0 tok/s при 60k, 38.0 при 150k; REPORT-PREFILL1e).
   Это путь HIP-форка, не Vulkan, поэтому в подгонку не входит.

## Результаты

Эффективность плотной модели на Vulkan (без флеш-внимания):

| семейство | n | медиана | min–max |
|---|---|---|---|
| RDNA3 + NVIDIA (для предложения) | 20 | 0.72 (квартили 0.67 / 0.77) | 0.51–0.84 |
| RDNA2 | 9 | 0.81 | 0.69–0.87 |
| NVIDIA | 11 | 0.74 | 0.51–0.84 |
| Intel Arc | 4 | 0.43 | 0.32–0.59 |

Одна карта, разные источники: RX 7800 XT даёт 0.73 (scoreboard), 0.77 (с флеш-вниманием), 0.60 (комментарий, другая
сборка). Значит, для одной карты разброс около ±13 %.

MoE на Vulkan: RX 7900 XTX, 57.6–62.3 tok/s, эффективность 0.12–0.13. Это в 5–6 раз ниже, чем у плотной модели на той же
архитектуре. Согласуется с обсуждением [#17751](https://github.com/ggml-org/llama.cpp/issues/17751) (тормозит
`mul_mat_ids`).

Сравнение с текущим коэффициентом установщика `efficiency.gpu = 0.5`:

| карта, модель | измерено, tok/s | прогноз с 0.5 | ошибка | прогноз с новым коэффициентом | ошибка |
|---|---|---|---|---|---|
| RX 7800 XT, плотная Q4_0, без FA | 118.3 | 81.5 | −31 % | 109.1 (0.67) | −8 % |
| RX 7900 XTX, MoE Q4_K_M | 62.3 | 240 | +285 % | 57.6 (0.12) | −8 % |

Вывод для PUB3: текущий коэффициент занижает плотный Vulkan примерно на четверть и завышает MoE на Vulkan в несколько раз.
Вторая ошибка опаснее: установщик на AMD с Vulkan может обещать скорость, которой не будет.

## Что НЕ проверено

- Таблицы сняты через пересказ страниц инструментом WebFetch, построчно по исходным страницам не сверял.
- Пиковая пропускная способность всех карт, кроме RX 7800 XT (624 ГБ/с, сверено через поиск), взята из спецификаций по памяти.
- Размер Qwen3-30B-A3B Q4_K_M (около 18.6 ГБ) и активные байты MoE (около 2.0 ГБ) — оценки. Размер Llama 2 7B Q4_0
  (3.83 ГБ) взят со страницы той же архитектуры, сам файл не открывал.
- MoE на Vulkan: одна карта, один источник. Тот же пост даёт этой карте 99.8 tok/s на плотной модели, а в
  scoreboard — 182.6. Из-за этого противоречия коэффициент 0.12 — нижняя граница, а не подгонка.
- Флеш-внимание для MoE на Vulkan не разбирал.
- Сборки llama.cpp разные (от января до октября 2025), влияние версии не отделял.
- Подпись «оценка, ±X %» не выводится: `planner.py` и `report.py` не менялись.
- Калибровка на машине пользователя (установщик после реального замера) не проверялась.

## Что передать PUB3

- `efficiency`: для Vulkan dense 0.67, для Vulkan MoE 0.12 (пока нижняя граница). Для HIP и CUDA ничего не менять.
- Подписи: dense «оценка, ±20 %», MoE «оценка, ±50 %; мало данных».
- Этот отчёт и `catalog/speed-calibration-vulkan.json` — входные данные для PUB3.

## Тесты

Полный набор на рабочем дереве (`python3 -m unittest discover -s tests -v`, лог `/dev/shm/PUB5/tests2.log`, удалится
при уборке): 1115 тестов, 3 падения, 1 пропуск.

Падения (все в установщике, не в моих файлах):
- `test_audit_cli.InstallWithRunningServer.test_a_server_that_is_already_running_is_stopped_openly_and_does_not_degrade_the_result`:
  в аргументах сервера нет `draft-mtp`.
- `test_cli_report.Card.test_check_json_is_the_plan`: порядок кандидатов бэкендов `['vulkan', 'cpu']` вместо `['rocm', 'vulkan']`.
- `test_cli_report.Card.test_check_prints_the_plan_for_a_profile`: в выводе нет строки `cuda, vulkan, cpu`.

Причина: в рабочем дереве есть незакоммиченные правки чужой работы (Codex): `installer/universal/planner.py`, `cli.py`,
`backends.py`, `engine.py`, `install.py`, `tests/test_backends.py`, `tests/test_install.py`, `tests/fixtures/fake_llama_server.py`,
`docs/INSTALLER.md`. Те же три теста на чистом `HEAD` (`git archive HEAD`, распаковано в `/dev/shm/PUB5/head`) проходят:
`test_cli_report` 10 тестов OK, `test_audit_cli` 38 тестов OK. Мои файлы (`docs/`, `catalog/`, `reports/`) код не меняют,
поэтому на эти падения не влияют. Исправлять чужие правки не стал.

Во время прогона: мой первый запуск с `timeout 600` оборвался (exit 124) и оставил свой процесс; я его завершил по PID.
Работающий `llama-server` на порту 8094 (Occamy, `safe-run.sh`, старт 06:49) не мой, я его не трогал.
