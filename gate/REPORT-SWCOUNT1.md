# SWCOUNT1 — выключатели и счётчики

Дата: 2026-11-13. Итог: **готово** в рамках этой карточки. Изменения оставлены незакоммиченными. Автоматического включения кандидата нет.

## Что уже было и что добавлено

До этой работы в истории уже были GATE1b и SHADOW1 part A. Ворота умели парные сравнения, повторные волны, семейную повторную выборку и сравнение якоря; gateway уже умел отдавать выключенные по умолчанию счётчики SHADOW1. Это не менял.

В `proxy.py` уже попадали `usage` и `timings`, но из них не переносились `reasoning_tokens` и `timings.reasoning_budget`. Поле `reasoning_tokens` в записи прогона бралось из журнала событий агента и на данных QLEV1 было нулевым. Я добавил чтение полей сервера для JSON и SSE, суммирование токенов и состояния выключателя на прогон, а также метки срезов из манифеста задачи. Старые записи при загрузке получают значения по умолчанию и остаются пригодными для `--resume`.

Добавлено в gate:

- проверка предварительной регистрации выключателя (`always` либо условие, id, срезы, единица и бюджет по строкам качества);
- точная односторонняя граница Клоппера — Пирсона и подсчёт «сработал хотя бы раз» по семье задач либо разговору; несколько выключателей строки объединяются в одну долю;
- закрытие только строк качества со шкалой `score` 0–1. Скорость и бюджеты счётчик не закрывает. Множитель по среднему баллу сработавших единиц не применяется: используется консервативный множитель 1;
- чтение JSONL живого формата и записей экзамена, предохранитель с уровнем значимости `0,05 / число проверок` и функция раздельного отчёта якоря: ядро по прогонам, условный слой по объединённому счётчику;
- диагностический режим для заменителя «токенов за прогон больше порога».

В примере предварительной регистрации добавлено необязательное поле `switch`. По умолчанию выключатель ничего не включает; вердикт ворот по-прежнему содержит `automatic_enable: false`.

## QLEV1: проверка заменителя

В старых QLEV1-логах `reasoning_tokens` равен нулю, поэтому поставлен диагностический выключатель по полю `tokens` (токены ответа за прогон). Порог выбран выше максимума в обоих файлах: 52 164. Это намеренно даёт ноль срабатываний и воспроизводит контрольный расчёт нулевого случая; это не калибровка полезного порога.

Команды:

```text
python3 gate/gate.py gate/prereg.example.yaml /home/alisher/Desktop/AI/reports/qlev1/base/results.jsonl --token-counter-threshold 52164
python3 gate/gate.py gate/prereg.example.yaml /home/alisher/Desktop/AI/reports/qlev1/raw/main/results.jsonl --token-counter-threshold 52164
```

Вывод для `base`: 46 задач, 12 семей, 0 сработавших семей, верхняя 95%-граница **0,220922** (22,1%). Для `raw/main`: 56 задач, 14 семей, 0 срабатываний, верхняя граница **0,192636** (19,3%). Ни одна экзаменационная строка при δ=0,03 сегодня не закрывается счётчиком. Это совпадает с ручным расчётом FRESH1. Оценка «только по сработавшим прогонам» не добавлялась.

## Не делалось и ограничения

- Живой Shura и gateway не запускались: карточка запрещает трогать live на :8080 и сеть. Формат живой строки проверен локальным JSONL-тестом; gateway-файлы другой сессии не менялись.
- Причинное тождество токенов при молчащем выключателе нельзя подтвердить этими логами. Это условие честности самого механизма, а не статистический вывод счётчика.
- Множитель по среднему баллу сработавших единиц оставлен равным 1 даже при большом числе срабатываний. Это разрешённый консервативный вариант; такой множитель потребовал бы отдельной оценки.
- Реальный QLEV1-порог не подбирался: старые логи не содержат новых полей рассуждения, а выбранный контрольный порог специально выше наблюдавшегося максимума.
