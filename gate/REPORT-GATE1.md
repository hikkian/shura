# GATE1 — отчёт

## Сделано

Добавлен небольшой Python-инструмент в `gate/`. Он читает предрегистрацию YAML/JSON и результаты JSONL, проверяет одного заранее названного кандидата, парность задач, число повторов `k` и одинаковые seed/rep у кандидата и контроля. Для каждой строки считает разницу «кандидат минус контроль», парный 95%-й bootstrap-ДИ по задачам и по семьям, точечную таблицу переворотов задач и зону green/red/grey. Красная зона также выставляется при нарушении бюджета. Целевая строка проходит только при нижней границе выше нуля; улучшение разрешено засчитывать только для `agent` и `personal`. Инструмент ничего не включает автоматически.

Пример предрегистрации и результатов лежит в `prereg.example.yaml` и `example-results/`.

## Рабочие характеристики — симуляция

В `REPORT-LL3b.md` указано σ парной разницы по задачам 0,221 на 12 задачах. Для ориентировочной таблицы использована нормальная модель независимых парных средних: `n=12`, `k=2`, σ=0,221 при `k=1`, 5 000 симуляций на ячейку, seed 20261112. Решение «проходит» здесь означает нижнюю 95%-ю нормальную границу выше `−δ`. Это параметрическая симуляция по сводной σ, а не повторный расчёт по сохранённым сырым данным A/A.

| δ | эффект 0 п.п. | −5 п.п. | −10 п.п. | +5 п.п. | +10 п.п. |
|---:|---:|---:|---:|---:|---:|
| 0,05 | 24,6% | 4,0% | 0,4% | 64,6% | 91,9% |
| 0,12 | 78,8% | 39,2% | 9,7% | 96,6% | 99,8% |
| 0,15 | 91,8% | 63,8% | 25,3% | 99,2% | 100,0% |

При этих `n`, `k` и σ допуск 0,12 даёт около 79% прохождения безвредного изменения и около 39% при потере 5 п.п. Значения отличаются от оценки в MASTER §5а (96% и 64% для δ=0,12), потому что там использована другая ошибка оценки 0,035. Текущая симуляция показывает зависимость результата от явно заданных `n`, `k` и σ; она не подтверждает исторические проценты для иного σ.

## Не сделано / ограничения

- Нет зон П0 (тождество, KL, top-8, экспозиция, кеш, MTP и пары скорости), автоотката якоря «стек против Tiel/DEPLOY2», режима «поезда», журнала решений и контроля лимита восьми обращений к запечатанным задачам.
- Повторные заходы пока представлены только делением α на число заранее заданных `looks`; CLI не объединяет отдельные волны новых задач и не проверяет их свежесть. Непрерывные границы и оценка числа ночей для гипотезы последовательного потока не реализованы.
- Результаты должны уже содержать пересуждённые оценки для обеих сторон. Хранение сырых ответов и запуск общего судьи инструмент не выполняет.
- Рабочая характеристика рассчитана параметрически, не на исходных A/A записях. В полной процедуре не симулированы все строки, семейная зависимость, бюджеты и несколько кандидатов.
- Ревью Sonnet high не выполнено: в доступном окружении нет такого ревьюера/инструмента.
- Коммит и Barid finish не завершились из-за прав файловой системы. Команда коммита вернула `fatal: Unable to create '/home/alisher/Projects/shura/.git/worktrees/shura-integration/index.lock': Read-only file system`; Barid finish вернул `rb: Read-only file system: /home/alisher/Desktop/AI/.relayboard/board.json.lock`. Оба пути вне разрешённых для записи каталогов. Код и отчёт остались в рабочей папке, но не закоммичены, карточка не закрыта.

## Необычное

Проверка показала, что перенос оценки LL3b σ напрямую в малую выборку `n=12`, `k=2` даёт заметно меньшую мощность, чем табличная оценка из MASTER. Для принятия решений нужно закрепить именно шумовую модель и размер экзамена; число δ само по себе не задаёт мощность.
