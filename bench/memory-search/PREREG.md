# LL2 pre-registered decision rules (written 2026-11-08, before any query was run against any arm)

Everything here is fixed before the measurement. The code in `run_ll2.py` implements these rules and prints the verdict; nothing below
may be changed after the first full run (if a rule turns out unusable, the report says so and keeps the original verdict too).

## Data
- Records: synthetic, in the user's style (ru/en/mixed, preferences, procedures, facts, notes, quotes), no real personal data.
  Includes old versions (`supersedes`), soft-deleted records, external quotes, disputed records.
- Queries: positives (a relevant record exists; relevant set = expected keys) in groups
  `plain_ru`, `plain_en`, `code`, `mixed`, `typo`, `case`, `paraphrase`, `version`; negatives (`negative`: nothing relevant exists).
  Queries were written without looking at any arm's results (the typo group is generated by code from plain queries, fixed seed).
- Corpus sizes for latency/index size: 120 (the fixture), 1000 and 5000 (synthetic padding records generated from the fixture's words).

## Arms
`u61` — current store: FTS5 `unicode61 remove_diacritics 2`, query = OR of the words (stop words removed), prefix on the last word, bm25(4,1,3,1.5)
        plus +1.0 for a matching scope and +0.3 for `trust=confirmed` (the production `search()` code, called as is).
`tri` — FTS5 `trigram` table beside it (same columns, bm25 weights, same scope/trust bonuses); query = OR of the words of >= 3 characters.
`both` — reciprocal rank fusion (k = 60) of the `u61` and `tri` rankings, then the same scope/trust bonuses.
`stem` (exploratory, not part of the decision) — `u61` with every word of >= 5 letters cut to its first max(4, len-2) letters and prefix-matched.

## Metrics (positives unless stated)
- `hit@3`: a relevant record is among the first 3 results. Also `hit@1`, `hit@5`, MRR.
- `source_ok` (version/source accuracy, groups `version` and records with a superseded/deleted/external twin): the top-1 result is the
  current record, not the old version, a deleted one or the external quote twin.
- `extra_tokens`: estimated tokens (3 chars per token) of the injection block entries (passport + title + first 240 chars of the body)
  of the top-3 results that are NOT relevant, averaged per positive query; and for negatives: tokens injected at all.
- operating threshold: for every arm, the lowest score threshold such that the share of negatives with at least one result above it is <= 10%.
  `extra_tokens` and `hit@3` are reported at that threshold (results below it are not injected).
- latency: p50/p95 of `search()` over the fixture's queries at 120, 1000 and 5000 records; index size (bytes of the FTS tables).
- Confidence intervals: 95% paired bootstrap over queries, 10,000 resamples, seed 20261108.

## Decision 1: trigram
`tri` or `both` WINS over `u61` only if ALL hold:
1. hit@3 over all positives is higher by >= 5 percentage points and the lower bound of the paired 95% CI of the difference is > 0;
2. in each of the groups `plain_ru`, `plain_en`, `code`, `version`, hit@3 is not lower than `u61` by more than 2 percentage points;
3. `extra_tokens` per positive query at the operating threshold is not higher than `u61`'s by more than 10% (relative);
4. p95 latency at 1000 records is <= 20 ms.
If both `tri` and `both` win: take `tri` unless `both` is better by >= 2 percentage points of hit@3, then `both`. If only one wins, it is chosen.
If nothing wins: `u61` stays; `memoryTrigram` is NOT added. If a trigram arm wins: add the flag `memoryTrigram` (default false) to `lifelong_store`,
with tests; the product's behaviour with the flag off stays byte-identical.
`stem` is reported next to the verdict; if it satisfies the same four conditions, the report says it is a cheaper alternative to look at, but the
verdict above is not changed by it.

## Decision 2: auto-help (`memoryInject`) or index + tool
Facts measured without a model: (a) `H` = hit@3 of the best arm on the "realistic message" groups
(`plain_ru`, `plain_en`, `code`, `mixed`, `typo`, `case`, `version`), not counting `paraphrase`; (b) `F` = share of negatives with an injection at the
operating threshold; (c) `C` = the compact index size (tokens at 3 chars per token) for N = 50, 100, 200 records of the fixture's style, against the
1500-token budget of DESIGN 3.5 A.
- `B_default_candidate`: H >= 0.85 and F <= 10% and the index no longer fits the budget at N = 100 (the model cannot see all records, so search
  help on the first message adds real reach).
- `B_optional`: H >= 0.85 and F <= 10% but the index still fits at N = 100 (the model sees every record; help is a convenience).
- `A_only`: H < 0.85 or F > 10% (injecting the user's message verbatim would put wrong notes into the prompt too often).
Result is a recommendation for the flag `memoryInject` in LL6; the CACHE1 prefix check stays an LL6 duty.

## Decision 3: embeddings
"Not needed now" if the best arm's hit@3 over every group except `paraphrase` is >= 0.85. Otherwise "needed later" (and the failing groups are
listed). Never a download in LL2; no embedding model is touched.

## Clarifications written before the first run (2026-11-08, still before any query touched any arm)
1. `both`: the fused score is the SUM of the two arms' scores (a result found by one arm only counts with that arm's score; the other adds 0).
   The first draft said "reciprocal rank fusion"; RRF throws away score magnitude and the operating threshold needs it, so RRF is replaced.
   The scope/trust bonuses are applied once, inside each arm's score, not again after the sum (the sum would otherwise count them twice: they
   are added once to the fused score instead).
2. The operating threshold is tuned on the fixture's negatives and therefore optimistic; the report also gives a 2-fold estimate (thresholds tuned
   on the odd-numbered negatives, false-injection rate measured on the even-numbered ones and the other way round). The verdict uses the plain figure
   as written above; the 2-fold figure is shown next to it.
3. Scope is not used (all records are `global`, `scope=None` in every search), so the scope bonus never fires; the trust bonus (+0.3 for confirmed) does.
4. Index size is the sum of the FTS5 shadow tables' payload bytes (`_data`, `_idx`, `_docsize`, `_content`), measured in a database on tmpfs.
5. Latency is measured on tmpfs (CPU cost only), one thread, after a warm-up pass, nice 19; it is a comparison between arms, not an absolute promise.
6. Estimated tokens = ceil(characters / 3.0).
7. Arm `tri` is defined as the OR of ALL TRIGRAMS of every query word (at most 80 distinct trigrams per query), not one quoted substring per word:
   an FTS5 trigram phrase must occur whole, so a word with a slip could never match; the OR of trigrams is what gives typo, case and word-ending
   tolerance. The word-as-substring form is kept as the exploratory arm `triw` (reported, not deciding), next to `stem`. `both` = `u61` + this `tri`.
   Written after seeing a toy example fail (the word "Mizzan" found nothing under the word-substring form), before any fixture query was run.
8. Decision 2 uses H = hit@3 AT THE OPERATING THRESHOLD over the realistic groups (what injection would actually deliver), and F = the 2-fold
   false-injection estimate (the plain rate is <= 10% by construction). The edge guard in condition 3 is: allowed extra tokens = 1.10 x u61's + 1 token.
9. `negative_deleted` has 4 queries (2 were dropped at review, see fixtures/REVIEW-NOTES.md); expected keys of some `version` queries were widened
   to every live record that answers them (same file). Both changes are from before any measurement.
